## 1. 最终使用方式与当前状态

电脑、手机和 iPad 打开同一个 HTTPS 网址，登录同一个私人账号。课程、课件原件、阅读版、标记、笔记和进度统一保存在服务器。电脑导入后，iPad 刷新书架即可读取；iPad 保存标记后，电脑重新载入同一课件即可看到。软件升级在服务器完成，各设备刷新页面使用新版本，无需分别安装三个应用。

首版采用在线网站，离线阅读、离线编辑及恢复联网后的自动合并另行设计。现有 Windows 本地版继续保留其离线能力；本地库与网站库不会自动双向同步。迁移后以选定的服务器库为日常使用的主库，避免两边各自修改。

## 2. 推荐架构

```text
电脑 / 手机 / iPad 浏览器
         │ HTTPS：同一私人域名
         ▼
反向代理 + 全路径身份验证
         │ 仅受信任的内部连接，支持 WebSocket
         ▼
PLW：Streamlit 外壳 + 独立阅读组件 + 服务层
         ├── SQLite：课程、关系、进度、标记、版本
         ├── 持久数据卷：原件、阅读 PDF、Markdown 及历史版本
         └── 转换任务队列 → 隔离的 PPT 转换工作进程
                   │
                   └── 完整备份 → 独立备份存储
```

首版保留现有 Python/Streamlit 和业务服务，使用一台服务器、一个应用实例及持久磁盘上的 SQLite。数据库不放在浏览器、不放在临时容器层，也不由同步盘或多台服务器同时共享打开。继续使用短事务、写入屏障、外键约束和版本检查；出现实测并发瓶颈后再评估 PostgreSQL。

推荐先验证 Linux 容器部署，便于重建依赖与版本回退。当前程序存在 Windows 专用实现，尚不能直接上传后在 Linux 运行。Windows 云主机可用于移植对照，但不能把桌面 PowerPoint 自动化直接当作长期服务器转换方案。

Streamlit 的 `st.App` 支持路由和中间件；官方将该 API 标为实验性。当前锁定 1.65.0，升级必须重跑上传、WebSocket、阅读及身份验证回归，不自动追随新版本。[st.App 官方说明](https://docs.streamlit.io/1.57.0/develop/api-reference/server/st.app)

## 3. 必须先完成的改造

### 3.1 数据与 Windows 依赖

| 现有依赖或行为 | 改造与验证要求 |
| --- | --- |
| `launch.py`、`locking.py` 使用 `msvcrt` | 抽象跨进程锁，分别实现 Windows/Linux；验证并发写入、进程退出释放锁、备份与恢复互斥 |
| 存储边界、SQL 校验包含 Windows 路径规则 | 独立迁移来源元数据和路径约束；托管内容使用相对存储键，平台路径由配置解析；保留路径越界及符号链接防护 |
| 上传资料的 `original_path` 当前记录服务器托管目标 | 不把该字段误认作客户端真实位置；保留用户文件名、来源类型及哈希，迁移不得破坏现有记录 |
| 本机 `E:` 目录、PowerShell 路径、PDF 工具 Python 路径 | 服务器使用独立配置和固定依赖镜像；PDF 工具纳入项目依赖，不依赖 Codex 缓存或用户主目录 |
| “打开原件”调用服务器的系统程序 | 网站改为经过认证的原件下载；用户在自己设备上选择兼容软件打开动画 |
| 电脑绝对路径引用、手动填写 PDF 路径 | 网站只提供文件选择上传；手工导出的 PDF 也通过上传绑定版本，不暴露服务器文件系统操作 |

迁移前生成完整备份，先在复制出的数据集验证。数据库版本只递增，并记录迁移结果；旧程序遇到新 schema 应拒绝写入。验证失败保留原库及文件，通过活动数据集切换回滚，不覆盖旧库。

### 3.2 PPT 阅读版转换

原生 PDF 直接进入阅读流程。PPT/PPTX 保存原件后排队生成静态 PDF，界面分别显示“已保存”“转换中”“可阅读”“转换失败”，关闭浏览器不丢失任务。转换工作在长事务和全局写锁之外运行，仅在提交结果时短暂加锁，避免一个大课件阻塞其他设备保存标记。

优先做 LibreOffice 无界面转换验证；官方提供 `--headless`、`--convert-to` 和独立用户配置目录参数，但这些参数本身不保证课件排版与 PowerPoint 一致。[LibreOffice 命令行说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)

验收样本应覆盖中文字体、机器人运动学公式、上下标、SmartArt、图片、表格、旧 `.ppt`、复杂背景和分步动画。逐份比较页数及关键页面；静态转换不承诺保留动画。字体必须按授权安装，缺失字体应报告。

工作进程应限制时间、内存及并发数，使用独立任务目录和低权限账号，禁止宏执行、限制外部资源访问。崩溃、超时、重启后的任务必须可重试且不覆盖已有阅读版本。首次上线可以保留“上传已从 PowerPoint 导出的 PDF”回退入口；原 PPT 始终保留，转换质量未达标时不得阻塞已经保存的文件。

Microsoft 明确不推荐或支持无人值守、非交互式服务器 Office 自动化，并指出界面阻塞与死锁等问题。因此，现有本地 PowerPoint 转换仅作为本地版能力保留，不直接迁为网站服务。[Microsoft 官方说明](https://learn.microsoft.com/en-us/office/client-developer/integration/considerations-unattended-automation-office-microsoft-365-for-unattended-rpa)

### 3.3 身份认证和 HTTPS

首版只允许一个指定账号，不开放注册。优先评估成熟的认证网关或 ASGI 中间件，依据用户可用的登录服务选择 OIDC 或受维护的本地认证实现。Streamlit 内置 OIDC 可提供登录身份，但自定义资源路由仍须验证覆盖情况，不能只在页面中检查 `st.user`。[Streamlit 身份认证说明](https://docs.streamlit.io/develop/concepts/connections/authentication)

上线验收必须覆盖以下边界：

- 未登录无法访问课程信息、WebSocket 会话、上传接口、PDF、阅读组件资源、原件及备份下载；仅登录所需路由公开。
- 复制已登录的 PDF 链接到无痕窗口仍被拒绝；过期、注销或撤销会话后不能继续读取或写入。WebSocket 会话也必须处理失效。
- 会话 Cookie 使用 Secure、HttpOnly 及合适的 SameSite 设置；保留 CORS/XSRF 防护，限制登录尝试，密钥放在服务器私密配置中。
- 只暴露 HTTPS 入口，应用端口仅允许内部访问；数据库、托管目录和备份目录不设为公开静态目录。日志不记录密码、会话令牌或文件内容。
- 反向代理保留外部 Host，正确传递 HTTPS 协议并支持 WebSocket Upgrade；只信任明确的代理地址。否则当前同源检查可能把合法 PDF 请求拒绝为 403。
- 上传体积、代理超时、转换超时和磁盘配额一致。现有限额为单份 200 MiB、每批最多 20 份/500 MiB；服务器首发值须经内存和弱网测试确定，界面显示实际生效限制。

## 4. 多设备保存与更新

多个设备可以同时登录同一账号，但仍可能同时编辑同一笔记或标记。写入请求携带记录版本，服务端发现旧版本时返回冲突提示并保留本次编辑内容，让用户重新载入或另存；不得用最后一次提交静默覆盖。阅读位置按保存时间更新也需要明确规则，不能由长时间挂起的旧页面把进度倒退。

首版以“保存成功后，其他设备重新载入看到最新内容”为验收目标。实时推送、多人协作和离线编辑不是首发承诺。断网时明确显示未保存，保留可重试的编辑内容；重新连接后核对版本和请求 ID，避免重复导入或重复创建标记。

软件更新采用版本化构建：备份 → 暂停写入并完成/停止转换任务 → 验证新版本与必要迁移 → 切换服务 → 检查关键功能。没有数据库迁移时可回退程序版本；有不兼容迁移时必须把程序和完整数据副本一起回滚，并说明会放弃哪些升级后写入。切换前保留这些新增数据的副本，不直接让旧程序写新 schema。

## 5. 备份与迁移上线

完整备份沿用现有清单和校验设计，包含数据库、托管原件、阅读 PDF、Markdown 及历史版本。外部引用文件明确列为未包含；迁移到网站前选择转为托管上传，或保留不可远程读取的状态，不能把本机路径当作可访问课件。

建议上线初期每日自动完整备份，升级和迁移前另做一份；保留周期依据容量和预算确定。备份放在与主服务分离的存储中并限制访问，密钥单独保存。恢复必须先解包到临时数据集，检查清单、SHA-256、数据库完整性及外键，再切换并保留回滚副本。至少演练主文件缺失、损坏压缩包、空间不足和恢复中断，记录实际恢复时间；同一服务器上的一份副本不足以应对整机损坏。

首次真实资料迁移须先完成合成数据演练，再明确要迁移的完整备份范围。校验课程/资料/版本/标记数量、关键关联及文件哈希后才将网站设为主库。本地原库保持原样留存；迁移窗口内暂停两端写入，避免出现未计入的增量。

## 6. 按依赖执行的阶段与验收

| 阶段 | 交付与涉及模块 | 验收标准与回退 |
| --- | --- | --- |
| W0：部署前移植 | 配置、`launch.py`、锁、存储、schema 迁移、依赖构建 | Windows 回归通过；Linux 合成导入/保存/完整恢复通过；路径攻击被拒；失败保留当前本地版 |
| W1：转换任务与浏览器流程 | 转换适配器、持久任务状态、上传 PDF 回退、下载原件 | PPT 样本逐页比对；任务超时与重启可恢复；转换期间其他设备可保存；失败保留原件与旧阅读版 |
| W2：私人访问边界 | 登录、授权中间件、HTTPS 代理模板、受保护下载 | 未登录/过期/复制链接/直接接口/WS 测试全部通过；应用端口无法直接外部访问；失败保持服务未公开 |
| W3：试部署与备份 | 持久数据卷、容量监控、备份任务、恢复手册 | 用合成库在目标服务器完成备份/恢复/升级/回滚；重启不丢数据；按实测调整上传限额 |
| W4：真实设备验收 | 响应式阅读、冲突处理、连接恢复 | 电脑、手机、真实 iPad Safari 在不同网络登录；分别导入与读取同一资料；验证页码、标记、笔记、中文文件名、弱网重试和冲突提示 |
| W5：正式迁移 | 已确认范围的完整备份、迁移报告、版本化发布 | 文件哈希与关联核对通过，用户确认核心课件可读；本地副本保留；异常按报告切回旧服务/数据集 |

W0–W2 的源码与合成验收可先推进；W3 需要确定服务器与域名，W5 需要明确真实资料迁移范围。尚未实际执行本表的云端部署、Linux 移植或真实 iPad 验收。

## 7. 费用与下一轮所需信息

费用包括计算实例、持久磁盘、独立备份存储、域名，以及可能产生的流量和认证服务费用。PPT 转换的内存峰值、课件总容量与访问网络决定配置；先用样本测量，再按所选厂商的实际购买页面报价。当前没有价格承诺或采购动作。

进入服务器选型前需要确认：

1. 每月或每年可接受的总预算；是否已有云服务器或域名。
2. 主要使用地区及网络，例如校园网、家庭 Wi-Fi、手机流量，用于选择访问稳定的部署地区。
3. 现有课件大致容量、最大单文件和预计增长量，用于确定磁盘、上传限制及备份保留期。
4. 可使用的登录方式，以及是否愿意使用额外认证服务；账号仍限定为本人。

无需在聊天中发送服务器密码、私钥或支付信息。选型确定后再给出具体配置、费用清单和部署步骤；真实学习资料迁移范围单独列明。

# 设备课件下载库（2026-10-21）

用户要求：下载一次，长期复用；提供一键更新，将所有已上传课件保存到当前设备。经说明电脑文件夹与 iPad 网页权限差异，用户选择了解应用内下载库；本轮按应用内下载库实现。它不是仅保留最近三个文档的内存缓存，也没有自动过期或按 LRU 删除设备文件。

## 使用方式与保存范围

课程书架新增“此设备课件下载库”，包含“一键更新全部课件”“检查更新”“申请长期保留”、逐份状态与进度。批量范围是当前学习库所有未移除课件的最新 PDF 阅读版，以及托管的 PDF/PPT/PPTX 原件，包含其他课程和已归档课程。不是只下载当前打开的一门课；旧阅读版本若单独打开，也会保存到设备。

下载完成的字节作为 Blob 写入当前网站的 IndexedDB，和浏览器读取实例、页面生命周期分开。打开课件时先从设备读并验证大小/摘要，匹配才交给 PDF.js；关闭网页、刷新、退出 PLW 登录不会由应用删除下载库。内存中的三个文档淘汰策略仍用于释放解析器资源，不再影响已经保存的文件。相同内容的阅读版与原件只保存一份字节，但分别保留名称和角色。访问令牌、下载能力 URL 和服务器绝对路径不写入设备清单。

更新时对照当前文件标识和 SHA-256，已保存且未变化的不下载；新增、变化或本机校验不符的文件重新下载并校验后保存。Blob 与清单在同一个数据库事务中写入，失败不能把未完成文件标记为已保存。已完成文件在中断后保留，下次补齐未完成文件；未完成单个文件的部分字节不跨页面关闭续传。一次连接内部仍支持有限的断点续传。旧版本、云端已移除文件的本机内容不自动删除。磁盘配额不足明确报错并停止，不擅自腾空间删除旧课件。

首批下载仍受服务器出口与 Tailscale 路径影响，本功能不提高第一次传输速度。复用已下载 PDF 不再依赖 PDF 内容下载，仍需本机读取、摘要校验和渲染；这是预期速度改善，没有真实设备时延承诺。网站外壳、PDF.js 脚本、字体等仍可能在线加载，本轮不宣称整站可离线冷启动，也没有离线批注同步功能。

“另存文件”从已保存的本机 Blob 导出一份普通文件，不再次从服务器下载。电脑与 iPad 的下载库各自独立。

## 长期保留的边界

点击更新时申请 Storage API 持久保存，并显示浏览器实际批准结果和估计的使用量/配额；没有批准时明确显示仍可能被浏览器回收。普通刷新、关闭网页、设备重启不是“清除网站数据”。用户在浏览器设置或清理工具中删除本站数据，可能删除这台设备的下载库；服务器原件保留。隐私模式不作为长期保存方式推荐。

浏览器的持久保存不是独立本地文件的绝对保留保证。WebKit 官方说明，默认 best-effort 存储可能因总配额、系统空间压力或长期未使用而回收，网站可通过 persist() 请求持久模式，是否批准由浏览器启发式决定。来源：https://webkit.org/blog/14403/updates-to-storage-policy/ 。产品显示实际状态，不把“发起申请”等同于“已批准”。

# 2026-10-18：整份接收并校验后本地阅读

用户最新截图为《第二讲-机器人结构与驱动方式.pdf》第 5/54 页再次白屏。兼容修复消除了缺少 Map 方法的错误，但并没有消除范围读取遇到网络内容停顿时卡住的设计问题。此次不再要求切换热点，也没有认定购买带宽即可解决。

## 已有证据与判断

此前同步采集记录中，两个 64 KiB PDF 范围响应各有约 52/51 秒的数据间断，直到采集结束仍未收齐；服务器未出现 CPU/内存饱和或 OOM。另一次经过核验的 SSH 通道记录中，444 个 PDF 请求完成，没有上述长停顿。公网上传快只能说明该方向的上传表现，不能证明服务器下行带宽足够，也不能据此认定云主机购买了某个带宽档位。

阅读器当前将新的页内容、缩略图所需 PDF 片段交给 PDF.js 按需请求。即使一些页已经显示，后续页仍可能等待一个未完成的响应；仅缓存 PDF.js 文档对象不能使尚未接收的内容变成本地文件。因此，兼容修复、文档对象缓存和服务器健康检查均不足以证明持续阅读已经修好。

## 这次改动

先在当前浏览器内存完整接收 PDF，按服务端登记的大小和 SHA-256 校验，再把字节数组交给同版本官方 legacy PDF.js。正常传输每份 PDF 一次请求；解析、翻页与缩略图不再向服务端索取 PDF 内容。

接收过程中显示 MB 进度；连续 15 秒没有收到数据会中止当前连接，从已经接收的位置继续，最多自动重试三次；总接收时间最多十分钟。续传必须返回精确的起点、终点、总大小及身份编码，最后仍须整文件摘要相符。登录失效、HTML 响应、错误长度或摘要不符会明确失败。失败提供独立的“重试读取”按钮，不冒充保存重试，也不无限等待。

保留最近三份文档及 96 MiB 原始 PDF 字节预算的内存缓存，预算不是整个浏览器堆内存上限。切换回来在缓存仍保留时复用文档；逐出、资料版本改变、数据集/访问入口改变或显式重载会释放文档并中止尚未完成的下载。未确认保存的操作模型仍保留。关闭/刷新浏览器、超出缓存预算后不保证免下载，没有加入磁盘或 IndexedDB 永久缓存。

首次必须接收完整文件，等待仍取决于网络速度；本次不是扩大带宽，也不改善上传吞吐。PDF.js 支持脚本、字体、CMap/WASM 等资源仍可能独立加载，不能把“没有后续 PDF 内容请求”等同于完整应用已经支持离线运行。

## 独立更新

基线只接受 `plw:0.3.1-reader-compatfix-20261018` 及其已记录源码和供应清单，目标 `plw:0.3.1-reader-fullfilefix-20261018`。更新仅复制 reader.js；保留兼容库、认证、路由、账号、资料和数据库结构。安装先核对当前镜像、离线构建并做隔离检查，再创建完整备份并切换镜像；健康失败会恢复原镜像。服务健康检查仅是启动门槛，不能代替阅读验收。

若当前镜像与基线不同，安装器停止，不能绕过检查继续。没有自动获取云端密码，也没有在此轮远程部署；本地一条 PowerShell 入口通过已核验主机密钥的公网 SSH 发送小更新包，密码仅在用户本地终端输入。

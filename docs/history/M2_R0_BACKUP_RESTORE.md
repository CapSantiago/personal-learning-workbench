## 1. 当前目录与保护范围

默认 M2 工作区为 `E:\Projects\PLW\.sandbox\m2`。自动化测试使用 `.sandbox\test-runs` 下随机命名的独立目录。以下路径相对 M2 工作区：

```text
control/
  active.json                 当前活动数据集指针
  .write.lock                 应用写入、备份与恢复共用的锁
  restore-journal.json        最近一次恢复的阶段与旧/新数据集身份
  *.tmp                       原子写入失败时可能保留的诊断文件

datasets/<dataset-UUID>/
  plw.sqlite3
  config.json                 格式版本与本数据集 UUID
  managed/<material-UUID>/... 托管正文
  notes/<note-UUID>/<revision-UUID>.md
  .staging/<operation-UUID>/... 导入暂存区；未完成操作会阻止完整备份

backups/<backup-UUID>/         普通完整备份
rollback/<backup-UUID>/        恢复前及回滚前完整副本
sources/                      合成导入来源；不属于托管正文
```

M2 界面有“课程工作台”“学期管理”“资料管理”“数据与备份”“项目进度”五个导航项。首次仅在点击“创建 M2 合成工作区”后初始化；普通查看不会创建学习数据库。

| 内容 | 完整备份是否包含 | 说明 |
| --- | --- | --- |
| SQLite 一致快照 | 是 | 全部表、关系、迁移历史及操作记录 |
| 托管文件正文 | 是 | 包括已隐藏记录但尚保留的正文 |
| 全部保留的笔记版本正文 | 是 | 每个 `note_revisions` 都必须有对应文件，当前版本指针也检查 |
| 数据集配置 | 是 | `format_version`、来源数据集 UUID；恢复后新集使用新的 UUID |
| 外部引用的索引与历史检查信息 | 是 | 每条明确 `included=false` |
| 外部引用文件正文 | 否 | 创建备份、验证、恢复和回滚均不打开原文件 |
| 经确认永久删除的托管正文 | 不包含正文 | 保留资料记录与匹配的已提交删除凭据，并逐条列入报告 |
| 未完成暂存文件、未知内部文件 | 不静默忽略 | 阻止发布完整备份 |
| 程序源码、`.venv`、活动指针、锁文件 | 否 | 活动指针与锁属于本机控制状态，不能从备份照抄 |

笔记和任务目前没有正式 M3/M4 业务界面。备份恢复的合成测试直接建立相关数据，用于验证未来数据关系和多版本正文不会被遗漏，不能据此声称笔记编辑或任务管理已完成。

## 2. 创建完整备份

1. 在合成工作区创建学期、课程。需要演练资料时，在“资料管理”点击“生成合成来源样例”，然后逐份选择复制或引用模式添加资料。
2. 打开“数据与备份”，核对页面显示的当前数据集 UUID。
3. 点击“创建完整备份”。应用冻结该工作区的业务写入，保存 SQLite 一致快照和内部文件，再独立验证输出。
4. 查看报告的 `complete`、`path`、`id`、`count`、`size_bytes`、`external`、`deleted` 和 `manifest_sha256`。
5. `external` 中的 `recorded_status` 是数据库上次记录的状态。`reason=index_only_not_inspected` 表示本次只备份索引，不能从这个报告推断原文件现在仍存在。

当前页面把普通备份保存到工作区 `backups`，没有自由选择真实磁盘目录的生产入口。源数据集、备份目标与恢复新集互不嵌套；服务也拒绝向任何 `datasets` 子树存放备份，或将备份快照误当作活动数据源再次备份。

如果空间不足、来源正文缺失或发生复制失败，操作停止并保留未完成输出。应用不删除旧备份来腾空间。对失败或隔离的文件操作，可在“资料管理”展开“核对未完成文件操作”，点击“核对文件操作”；该功能仅核对已记录意图，不会接受未知文件、重新复制原始来源、删除残留或清空操作历史。仍未解决的失败或隔离记录会继续阻止完整备份。

## 3. 备份目录格式与独立验证

```text
<backup-UUID>/
  incomplete.json             创建记录；成功后也保留
  manifest.json               严格格式的 UTF-8 清单
  manifest.sha256             manifest.json 原始字节的 SHA-256
  complete.json               全部验证完成后才写入的发布标记
  payload/
    plw.sqlite3
    config.json
    managed/<material-UUID>/...
    notes/<note-UUID>/<revision-UUID>.md
```

`incomplete.json` 的存在不表示失败，因为创建记录始终保留。**只有 `complete.json` 存在且独立完整验证成功，才是可恢复的完整备份。** 仅有目录、清单中的 `complete=true`，或者此前屏幕上出现过成功提示，都不能替代重新验证。

没有独立落盘的 `report.json`。页面报告由验证结果派生，恢复不会把旧报告当作完整性依据。

验证过程包括：

- 检查清单版本、字段、类型、文件数量、规范相对路径、大小写冲突和重复 JSON 字段。
- 对清单原始字节、每个 payload 文件逐项校验大小与 SHA-256。
- 双向比较实际文件/目录集合与清单；未知文件、未知空目录、未登记正文或缺文件均失败。数据集内仅允许数据库记录可以解释的已提交操作空目录等明确例外。
- 拒绝绝对内部路径、盘符、UNC、`..`、备用数据流、Windows 保留设备名、歧义文件名、符号链接、目录联接、重解析点和硬链接。
- 对数据库执行 `integrity_check`、`foreign_key_check`，检查程序支持的迁移版本与校验和，并将实际 `sqlite_schema` 与应用内迁移建立的参考结构比较。额外或改动的表/触发器也会被拒绝。
- 从数据库快照重新枚举托管正文与全部笔记版本，核对文件清单、可信基线及外部引用/删除报告。经确认永久删除必须有实体、目标路径、哈希和用户确认值相符的已提交删除操作记录。

哈希用于发现内容与清单不一致，**不是数字签名，不证明备份来源可信**。目前不接受 ZIP，也不执行清单中的文件或外部路径；不自动升级更老备份格式或未知数据库版本。

## 4. 验证与恢复备份

恢复是整套数据集切换，不是把一部分表合并进现有库，也不会按外部引用路径回写原文件。

1. 在“数据与备份”的“备份目录路径”中输入一个完整备份目录。
2. 点击“验证并预览备份”。页面重新计算完整性，显示来源数据集、文件范围、外部引用未包含项及清单哈希。
3. 阅读“确认切换范围”，在“输入当前数据集 ID 确认恢复”中逐字输入**当前活动数据集 UUID**，然后点击“恢复并切换数据集”。
4. 应用再次核对当前指针与预览清单哈希。路径、清单或活动数据集变化后，需要重新预览；旧确认不能用于新的范围。
5. 应用先在 `rollback` 保存并验证旧活动数据集的完整副本。该步骤失败时不会创建可切换的新活动集。
6. 应用在新的随机 `datasets/<UUID>` 中恢复数据库、内部正文和新数据集配置，逐表核对内容摘要、逐文件核对哈希，并再次验证原备份。
7. 写入切换意图日志后，应用通过同卷原子替换 `control/active.json` 切换活动集。源备份、旧数据集和回滚副本均继续保留。
8. 页面重新加载新数据集；核对课程、资料及隐藏资料。正式任务/笔记界面仍待 M3/M4，相关关系由当前自动化测试核对。

真正的空工作区可在未初始化时进入“数据与备份”，预览并用 `EMPTY` 确认恢复；此时报告明确没有旧数据可备份。**已有 `datasets` 内容却丢失活动指针，不会被当作空工作区**，恢复会停止，要求先检查控制状态。

## 5. 中断判定与显式核对

日志保存在 `control/restore-journal.json`。启动时读取真实活动指针与日志中的旧/新 UUID，得出 `old_active`、`new_active` 或 `unrelated_active`；不根据修改时间猜测，也不自动切换。

| 阶段 | 含义 |
| --- | --- |
| `none` | 没有恢复日志 |
| `preparing` | 已记录恢复意图，正在准备恢复前副本 |
| `old_preserved` | 旧数据完整副本已完成；空环境明确没有旧集 |
| `copying` | 正在构造新数据集 |
| `ready_to_switch` | 新集验证完成，准备切换活动指针 |
| `complete` | 恢复完成，新集活动 |
| `failed` | 发生异常；必须结合实际指针判断是否已切换 |
| `rolling_back` | 当前新数据已保存，正在切回旧集 |
| `rolled_back` | 已切回旧集 |

未完成阶段、损坏日志，或 `failed` 但新集已经活动的状态，会阻止普通业务写入。界面引导到“数据与备份”检查；这不是数据库被清空。

在“恢复状态与回滚”中，输入页面当前数据集 UUID，点击“核对并结束中断维护”：

- **旧集仍活动**：验证旧库、资料基线和实际文件集合；确认尚未切换后把中断状态记为 `failed`。如果是已完成指针切换的回滚中断，则记为 `rolled_back`。保留未完成新目录。
- **新集已活动**：重新验证原备份及日志绑定的清单哈希，逐表/逐文件验证新集；通过后记录 `complete`。
- **指针与旧/新身份均不符，文件损坏，或丢失指针且已有未说明的数据集**：停止，不自动修补、重新初始化或删除数据。

“核对并结束中断维护”用于检查中断结果，不用于接纳用户在内部目录随意改过的正文。如果新集已正常投入编辑，再次与原备份逐表比较可能不同；此时应按当前操作结果处理，不能通过篡改清单消除差异。

## 6. 回滚恢复

当日志能够证明当前活动集是刚恢复的新集，且存在旧集与恢复前副本时，页面提供“保存当前副本并回滚”。

1. 阅读当前数据集 UUID 和恢复日志。
2. 在“输入当前数据集 ID 确认维护操作”中输入该 UUID。
3. 点击“保存当前副本并回滚”。应用先验证旧集与恢复前快照的一致性，再为当前新集生成完整副本；当前副本失败则不切换。
4. 应用切回旧活动指针，记录 `rolled_back`。恢复后的修改保留在新数据集和 `post_restore_backup` 指向的完整副本中，不自动合并到旧集。

旧集损坏会阻止回滚；不会把旧数据库单独覆盖到新文件集合上。指针替换失败时保留日志、两个数据集和完整副本，可以检查状态后重试。所有旧集、失败副本和历史备份均不自动清理。

## 7. 一致性、事务与异常边界

数据库快照使用 Python `sqlite3.Connection.backup()`，不是普通文件复制。整个数据库与正文备份过程由线程锁和 Windows 跨进程文件锁保护；普通课程写入、资料导入、删除与恢复共用工作区屏障。旧浏览器页面在活动集切换后不能继续写旧集。

该屏障约束 PLW 的合作进程，不是阻止用户或其他程序直接修改内部目录的操作系统访问控制。检查期间正文改变会通过基线/复制校验被发现，但不能宣称在任意并发外部修改或故障硬件条件下具有绝对保障。

| 故障 | 当前行为 |
| --- | --- |
| 预检、空间、版本或清单失败 | 不切换活动指针 |
| 复制权限失败、磁盘满、校验不符 | 保留未发布输出；原活动数据保留 |
| 旧数据回滚副本失败 | 停止恢复 |
| 新集复制或验证失败 | 保留失败新集与日志；旧集继续活动 |
| 指针切换前失败 | 通过实际指针确认旧集仍活动 |
| 指针已切换但随后报错 | 日志结合真实指针识别为新集活动，阻止普通写入直到核对或回滚 |
| 进程中断 | 启动读取日志；显式验证收尾或回滚，不自动猜测 |
| 旧集或当前新集损坏 | 不以不完整副本完成回滚；保留证据供检查 |

同卷原子替换减少切换窗口，但不能保证任何突然断电、设备缓存异常或整盘损坏后都成功恢复。同一块 E 盘内的代码、数据和备份不具备独立介质容灾能力。独立磁盘导出、容量管理、安全取消与大量资料性能验收留待后续正式数据启用规划。

## 8. 已执行验证与尚未验证事项

`tests/test_backups.py` 的 43 项专项测试已通过，覆盖：

- 两门课程、两个任务共享多份资料、跨课程资料关联、章节和笔记关联；完整恢复后逐表摘要相同。
- 托管正文、逻辑隐藏后保留的正文、有删除凭据的已删正文、外部引用，以及两份 Markdown 历史版本。
- 空环境恢复、恢复前副本、保留恢复后修改的回滚及逐文件哈希一致。
- 外部正文在备份恢复全程哈希、内容和修改时间不变；缺失外部引用仍明确只备份索引。
- 缺文件、正文/数据库/清单损坏、额外文件和空目录、未知格式/schema/表对象、路径穿越、绝对路径、大小写冲突与未知条目类型。
- NTFS 实际硬链接拒绝；其他共享路径防护由 storage 的专项测试另行报告。
- 复制权限错误、磁盘满、空间不足、恢复前副本失败、恢复复制失败、切换前/后指针失败、回滚指针失败的受控故障注入。
- 真实线程竞争：备份期间课程写入等待，快照保留备份开始时的数据。
- 中断日志保留、旧/新指针判定、显式核对后解除写入阻止、损坏新集拒绝收尾。
- 错配工作区不能污染备份目录；丢失指针不当作空环境；备份不能写进其他数据集。

“权限错误”和“磁盘满”使用故障注入，没有修改 Windows ACL 或真正填满磁盘。中断用受控异常与保留阶段模拟，没有拔电测试。完整操作系统断网、实际断电、故障硬件、大规模资料库、生产数据迁移和独立介质容灾尚未验证。M0/M1 的离线探针不等同于完整 OS 断网保证。

## 9. 技术依据与后续边界

- [SQLite Online Backup API](https://www.sqlite.org/backup.html)

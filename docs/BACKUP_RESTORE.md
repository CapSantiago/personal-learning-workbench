# 备份、恢复与回滚

适用版本：0.3.0，schema 3。此前手册保存在 history/M2_R0_BACKUP_RESTORE.md。

私人网站配置文件（账号密码校验值）独立保管，不进入学习库完整备份或程序发布包；恢复学习库后仍使用该服务器自己的登录配置。下载到手机/iPad的课件副本不自动回传，不能替代完整备份。

任务点击“完成”后只改变状态，并保留详情、完成时间和资料关联；完整备份与恢复包含“已完成任务”存档。恢复待办会清空本次完成时间，再次完成会记录新的时间。

课程顺序保存在数据库的 courses.position，随完整备份恢复。旧 schema 1/2 备份可恢复到新数据集并升级；升级前保留完整备份，验证新副本后才切换，原数据集继续保留以供回滚。

工作区根目录 `cache/<dataset>/` 的 OCR 文字与动画/视频副本属于可重建缓存，不在完整备份内。原托管 PPTX/PDF、笔记、标记及阅读版本仍全部备份。要长期保存 OCR 结果，请复制到 Markdown 笔记或导出文字。外部引用原件仍只保存索引，若原 PPTX 不存在，恢复后不能从静态 PDF 重建其动画/内嵌视频。

## 范围

正式工作区 `E:\PLW-Data`，普通备份 `E:\PLW-Backups`，恢复前及回滚前副本在工作区 `rollback`。合成测试仍使用 `.sandbox/test-runs`。

`control/active.json` 指向 `datasets/<UUID>`。完整备份包含：

- SQLite 数据库与 config 身份文件；任务、课程、章节、知识点、标记、阅读进度及关联。
- `managed/<资料ID>/...`：托管原格式文件，包括隐藏但未单独删除的文件。
- `reading/<版本ID>.pdf`：全部已登记阅读 PDF，包括旧版。
- `notes/<笔记ID>/<版本ID>.md`：全部已保存 Markdown 版本。

外部原格式文件不包含，逐条列入排除报告。外部 PPT 对应阅读 PDF 包含在 reading_pdf 清单项中，不能当作原 PPT 的备份。工作区 jobs 为未发布暂存内容，不计入成功正文；未完成内容操作会阻止完整备份成功。暂存内容不自动清理。

## 操作

1. 点击“创建完整备份”。应用冻结写入，使用 SQLite backup API，核对和复制全部内部文件。
2. 验证清单、SHA-256、文件集合、schema、SQLite 完整性和外键后才写 complete.json。没有成功标记的目录不是完整备份。
3. 恢复时输入备份目录，点击“验证并预览备份”。确认外部原件是否另有副本。
4. 输入页面显示的当前数据集 ID 确认。系统先保存恢复前完整副本，再恢复到新的 UUID 目录。
5. 旧 schema 1 备份先按旧结构验证，只升级新的恢复副本并验证。原备份不改写。
6. 再次确认来源清单未变化后切换活动指针。旧目录保留。
7. 打开恢复的课件，检查页码、文字和图形标记，检查笔记历史。

恢复不向外部引用路径写回文件，也不会扫描外部原件。报告里的外部状态来自上次检查记录。

## 回滚和中断

“保存当前副本并回滚”先备份当前数据，再验证旧数据与恢复前副本一致，最后切回。旧 schema 数据切回后主界面会提示备份并升级，不会在普通查看时偷偷迁移。

未结束恢复会阻止普通写入。先查看恢复日志，再点击“核对并结束中断维护”或回滚。指针和日志不匹配时不会猜测哪个目录较新。

阅读/笔记提交中断时，在“未完成的阅读副本与笔记操作”点击核对并重试。已校验暂存文件可继续发布。目标文件尚不存在时，可输入操作 ID 取消未发布操作，草稿保留；已有目标正文时不能通过取消绕过校验。

缺文件、校验失败、未知内部文件、失败导入和未完成内容操作会拒绝完整备份，不会只保存数据库然后宣称成功。旧数据、失败现场、备份均保留。不要手动修改活动指针或内部记录绕过验证。

普通备份与数据当前同在 E 盘，无法抵御整盘故障；请定期另存整个备份 UUID 目录到其他磁盘。

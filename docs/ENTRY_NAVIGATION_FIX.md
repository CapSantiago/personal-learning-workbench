# 私有入口 Forbidden 小更新

2026-10-17：云端旧镜像对所有 Sec-Fetch-Site: cross-site 请求返回403。实际直连对照为普通访问200、外部顶层导航403。手动在新标签页地址栏输入完整地址可暂时进入。

修复只允许根路径或登录页的无 Origin 顶层 GET 导航，仍需登录。跨站文件读取、iframe、写入、WebSocket、错误Host及Origin仍拒绝。源码修复为1381e66。

## 更新方式

包包含修复模块、离线Dockerfile、合成检查器、安装脚本和校验清单，不包含账号或学习资料。只适用于当前已验证镜像ID的0.3.1离线部署。上传到/root，核对发布包SHA-256后，解压到全新目录，例如/opt/plw-entry-fix-20261017。

执行 `bash install_entry_hotfix.sh`。脚本核对当前镜像及文件，复用本地基础镜像离线构建衍生镜像，在无网络、无正式数据挂载的容器内检查入口保护；然后通过现有容器创建完整学习库备份，保存旧部署环境文件，只切换PLW_IMAGE并重新创建服务。回环健康失败时自动恢复旧部署环境并尝试启动旧镜像。不会修改原离线包，不运行init，不迁移数据库或更换账号。

短暂中断后需要重新登录。保留Workbench公网连接；本工具不重启Tailscale，不解决DNS规则持久化问题。

## 验证边界

源码认证/云兼容测试在Windows运行。补丁容器合成检查、离线构建、正式库备份、切换镜像及自动回退必须在Linux执行后才能确认；本地不具备Linux Docker引擎。安装成功还需从实际设备点击外部入口并登录、确认学习库内容。

如需人工回退，使用脚本输出的精确旧环境快照恢复`/srv/plw/private/deploy.env`，再使用现有compose.yaml执行`up -d --no-build --pull never`。不要恢复或删除学习数据，也不要删除旧镜像。更新后的快照保留在主机，不放入Git或公开发布包。
